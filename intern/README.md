# 面談メモ — 面談の10分前に開く1枚

## 何を解こうとしているか

インターン42人（稼働は約半数）と個人面談をするとき、**1人ずつと話す前に
その人のことを思い出す時間が取れない**。

**ボトルネックは情報収集ではなく、面談の準備。**
だから作るのは「活動の可視化ダッシュボード」ではなく、**1人分の1枚**。
的が小さいので、データが多少欠けていても機能する。

## 絶対に外してはいけない前提

**監視にしてはいけない。**

この依頼は音声で届いた。理由は本人の言葉で
**「文字で書くと監視しているように読めてしまうから」**。
**「行動ログを集める」という立て方にした時点で、この仕組みは失敗する。**

守っている設計上の約束は3つ。

| 約束 | なぜ |
|---|---|
| **拾うのは、その人自身の面談だけ** | Slackの発言も、ドキュメントの編集履歴も見ない。行動を追跡していない |
| **本人が何かを書く必要はゼロ** | 「今週これやりました」を書かせるのは負担であり、既に否定されている |
| **本人にも同じ1枚を見せる** | 見せれば「共通の議題」、見せなければ「調書」。**同じデータでも意味が正反対になる** |

## 仕組み

```
面談を録音
    ↓
whisper.cpp でローカル文字起こし    ← 音声を外部APIへ送らない
    ↓
個人ごとのファイルに要約を追記
    ↓
次の面談の10分前に、その人の1枚を生成
```

**新しい入力を作らない。** 入力は面談そのもの。
だからインターン側の負担がゼロで、Slack→Google の移行にも影響されず、
チケット制の完成を待たずに今日から動く。

**初回は何も出ない。2回目から効く。**
「前回何を話し、何をやると言ったか」——42人分でこれを覚えているのは無理で、
実際に困っているのはここ。

## 1枚の中身

`sheets/2026-09-10_神永勇磨.md` が試作。構成は4つ。

| 見出し | 中身 |
|---|---|
| 前回やると言ったこと | 各項目に **その後どうなったか** を付ける |
| つまずいていそうなこと | 複数回持ち越している項目、偏っている領域 |
| 進んでいること | 触れないと、残っている項目だけが目立つ |
| **今回聞くとよさそうなこと** | ここが本体。**話すべきことの候補** |

### 「やったこと一覧」にしない

同じデータから作れるが、受け取られ方が正反対になる。

- **やったこと一覧** → 評価の材料に見える
- **話すべきことの候補** → 面談の準備に見える

だから最後の見出しを本体に置き、**質問の形**で書く。

## AIは間違う前提で作る

1枚の先頭に必ず入れる。

> このページはAIが過去の面談記録から自動生成しています。
> **事実と違うところは直してください。** 直した内容が次回に反映されます。

**本人が直せる形でなければ、誤りが誤りのまま判断材料になる。**
これは監視かどうかの問題であると同時に、精度の問題でもある。

## 決まっていないこと

1. **本人にも見せるか** — 上記のとおり見せる前提で設計しているが、要合意
2. **録音は誰が回すか** — **録音することを本人に伝えるのは必須。**
   黙って録るのは、この仕組みの目的と正面から矛盾する
3. **文字起こしをローカルのままにするか** — 人事の会話は財務データより機微かもしれない。
   財務側で作った門番（`agent/masking.py`）の考え方がそのまま効く

## 試作の材料

`geminiメモ/` の 2026-08-27 と 2026-09-07 の記録。
どちらも whisper.cpp のローカル実行で文字起こししたもの。

**2回分あることが重要。** 1回分では「前回言ったことがどうなったか」が作れない。
